# Plan: TUI Input Hardening for Tehuti CLI

## Bugs to fix

### B1. Mouse sequence leak → ghost text in input (HIGH)
**Symptom**: `9M;49MM49M9M9M` appears in chatbar while scrolling
**Root cause**: `MouseProvider` enabled at top level. Split SGR mouse coords (e.g. `<64;27M` arriving as `<` + `64;27M` in separate `useInput` calls) slip past `isMouseSequence()` filter.
**Files**:
- `src/utils/mouse.ts` — extend detector to catch all partials
- `src/cli/ui/hooks/useChatInput.ts` — buffer and reassemble partials
- `src/cli/commands/chat.ts` — `MouseProvider` should NOT auto-enable; mouse is for palette/editor only

**Fix**:
1. Add `MOUSE_FRAGMENT_BUFFER` ref in `useChatInput` to coalesce partial sequences
2. Tighten `isMouseSequence()` to also match `^\d+;` (start of coordinate chunk)
3. Change `autoEnable: mouseEnabled` to `autoEnable: false` and only enable inside palette/editor via explicit per-component MouseProvider
4. Add unit tests for: split sequences, fast scroll fragments, paste interference

### B2. Shift+Enter leaks raw escape `[27;2;13~` (HIGH)
**Symptom**: Typing Shift+Enter shows literal escape in input
**Root cause**: Shift+Enter arrives as CSI `\x1b[13;2~`. Ink's `key.shift && key.return` is sometimes undefined for the modified-Enter escape. The text-input branch falls through.
**Files**:
- `src/cli/ui/hooks/useChatInput.ts` — add explicit handler for `\x1b[13;2~` (Shift+Enter) and `\x1b[13;5~` (Ctrl+Enter) BEFORE the text input branch

**Fix**:
```ts
// Shift+Enter (CSI 13;2) and Ctrl+Enter (CSI 13;5) — handle BEFORE any text-branch
if (k === "\x1b[13;2~" || (key.shift && key.return)) {
  // insert newline
}
```

### B3. Fast typing drops characters (MEDIUM)
**Symptom**: Type fast → "cut characters like his"
**Root cause**: `setInput` is React state, each keystroke triggers full TUI re-render. 3700-line chat.ts has heavy useMemo deps that re-run.
**Files**:
- `src/cli/commands/chat.ts` — debounce `renderInput` re-render via `useDeferredValue` on `input`
- `src/cli/ui/hooks/useChatInput.ts` — buffer input with `flushSync` on rapid bursts

**Fix**:
1. Wrap `input` state with `useDeferredValue` for render, but keep raw state for cursor/send
2. Use `useTransition` to mark input updates as low-priority
